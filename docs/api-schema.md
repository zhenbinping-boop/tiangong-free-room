# 教务系统接口真源（jwxs）

本文档记录本项目实际依赖的教务系统接口与响应结构，**以抓包与源码破译为唯一依据**。
字段名与语义未确认前不得猜测 —— 曾因猜测导致登录从未成功（见 `docs/代码审查报告.md`）。

- 基址：`https://jwxs.tiangong.edu.cn`
- 系统：强智 URP，Spring Security，校方编号 `schoolId=100018`
- 实现位置：`crawler/jwxs_client.py`（登录与数据获取）、`crawler/parser.py`（结构映射）

---

## 1. 登录流程

| 步骤 | 请求 | 说明 |
|---|---|---|
| 1 | `GET /login` | 建立会话（`JSESSIONID` + `student.urpSoft.cn`，HttpOnly、会话级），提取动态隐藏字段 `tokenValue` |
| 2 | `GET /img/captcha.jpg?<rand>` | 4 位图形验证码，**必须同一会话**；用 ddddocr 识别 |
| 3 | `POST /j_spring_security_check` | 表单见下表 |
| 4 | `GET /student/teachingResources/freeClassroom/today` | 会话有效性判定：`200` 且未被重定向回 `/login` |

### 1.1 登录表单字段

```
lang=zh
tokenValue=<第 1 步提取>
j_username=<学号>
j_password=<见 1.2 加密公式>
j_captcha=<第 2 步识别结果>
username=<隐藏字段，空值>
```

### 1.2 密码加密公式（D1 破译）

```
j_password = md5( md5(pwd + "{Urp602019}") ) + "*" + md5( md5(pwd) )
```

- 定制版 `hex_md5(s, ver)` 在 `ver !== "1.8"` 时给原文追加盐值 `{Urp602019}`
- 两段各 32 位十六进制，中间以 `*` 连接，总长 65
- 页面加载的 `sm3/*.js` 是干扰项，登录**未使用**

### 1.3 已知坑

- **`tokenValue` 每次 `GET /login` 都刷新**，且登录失败后服务端也会刷新 → 重试必须重新 GET `/login`，不能复用旧值
- **不走 CAS**：`pt.tiangong.edu.cn` 明确拒绝为 jwxs 签发票据（返回"未认证授权服务"）
- 服务端错误码：`badCaptcha`（验证码错）、`badCredentials`（账号密码错）；两者可区分，用于决定是否换图重试
- **会话判定禁止使用页面文本匹配**，只能看受保护页的状态码与重定向目标（BUG-03 教训）

## 3. 数据接口（首选源）

```
GET /student/teachingResources/freeClassroom/today/{小节}?dayplus=0
→ { spareroomObjList: [ { acmcBuildingName, claroom: [ { classroom, classNumberOfSeats } ] } ] }
```

- `dayplus=0` 今天；明天接口见 §4
- **已过去的小节也会返回**（HTML 版会省略），这是选它作首选源的原因
- 返回集按 `acmcBuildingName` 过滤出目标楼栋，其余忽略

### 3.0 小节号支持逗号分隔（2026-09-16 实测确认）

`{小节}` 不止能填单个数字，**可以填逗号分隔的多个小节号**，服务端对这些小节取**交集**返回 ——
即"这些小节都空闲"的教室集合。

```
GET /student/teachingResources/freeClassroom/today/1,2?dayplus=0
→ 第 1 节与第 2 节都空闲的教室
```

实测（西区第一公共教学楼，89 间逐间比对）：

| 大节 | 单节返回 | 逗号合并返回 | 交集 | 并集 |
|---|---|---|---|---|
| 1（第1,2节） | 57 / 57 | **57** | 57 ✓ | 57 |
| 2（第3,4节） | 32 / 32 | **32** | 32 ✓ | 32 |
| 3（第5,6节） | 39 / 39 | **39** | 39 ✓ | 39 |
| 4（第7,8节） | 56 / 62 | **56** | 56 ✓ | 62 ✗ |
| 5（第9,10节） | 73 / 74 | **73** | 73 ✓ | 74 ✗ |

结论：五个大节全部符合**交集**语义（大节 4、5 明确排除并集）。
用它构建的 occ 掩码与逐小节查询**完全一致，0 处差异**。

因此每个大节只需 1 次请求，每栋 **10 次 → 5 次**。
（注意：合并查询无法区分"整大节无空闲"与"接口异常"，统一按**占用**处理，
比旧实现的"按未知处理"更保守 —— 见 `rooms_parser.records_from_slot_rooms`。）

### 3.0.1 `{小节}=0` 的含义

`/today/0` 返回该楼栋的**全部教室**，包括全天占满、不会出现在任何小节返回里的教室。
实测第一公共教学楼：`/today/0` = 92 间，而"至少有一节空闲"的教室 = 89 间，
多出的 3 间即当天全天占满的教室。**当前未使用**（全天占满的教室对用户无意义）。

> 这条也解释了"工作日教室数为什么浮动"：全天五大节都被占用的教室，
> 不会出现在任何小节查询的返回里。**该解释已由本次实测佐证，但仍未与教务系统页面人工比对。**

### 3.1 切换楼栋（关键坑）

```
POST /student/teachingResources/freeClassroom/today
表单：position="{校区号}_{楼栋号}"  &  xqm="{校区名}"
```

- **`position` 不是纯楼号**，而是 `校区号_楼号`（如 `01_51`）。
  只传楼号（`20` / `51`）服务端**一律 500**；不带 `position` 则 200 —— 曾据此误判"此路不通"
- `xqm` 取自页面隐藏字段 `id="xqm"`，默认兜底"东区"
- 取数前必须先切到目标楼栋，否则拿到的是上一次选中的楼栋

#### 返回范围取决于会话状态（2026-09-16 实测，修正了旧文档的自相矛盾）

旧版文档同时写着"一次返回全楼栋"和"必须先切换楼栋"，两者矛盾。实测结论：

| 会话状态 | `spareroomObjList` 返回 |
|---|---|
| 从未调用过 `select_building` | **默认校区（东区）的全部楼栋**（实测 17 栋） |
| 调用过 `select_building` | **只有当前选中的那一栋** |
| 尝试重置回全量 | **做不到** —— `position` 给 `03_` / `03` / `_` / `all` 均 500；不带 `position` 或给空串返回 200 但**不改变**已指定状态 |

另外实测：只传 `xqm={校区名}`（不带 `position`）**不能**切换默认校区 ——
返回集合始终是东区的那 17 栋。默认校区锁定为东区，无法改。

因此不存在"一次请求拿全校"的可能，跨校区必须逐栋切换。

#### 「今天是哪天」怎么确认（2026-09-16 实测）

接口本身**不返回日期**。但任何已登录页面的顶部都渲染了学期信息：

```html
<span class='span_bbzx'> 2026-2027 秋 第3周 星期三</span>
```

这是**服务端自己认为的今天**，可用作翻篇判据。`crawler/parser.py::parse_server_day()` 解析它，
`fetch_rooms.py::ensure_server_day_rolled()` 在抓取前与服务端的星期做比对：

- 一致 → 正常抓取；
- 不一致（服务端还停在昨天）→ 等待 30 分钟后复查，最多 4 次；仍不翻篇则**拒绝写入 today.json**，
  以非零码退出、保留上一次真实数据（详见 §5.2）；
- 解析不到标记（页面结构变了 / 未登录）→ 只警告，**不阻塞**（避免页面小改动就整天没数据）。

## 5. 数据模型映射

`today.json` 一节由 `crawler/parser.py` 产出：

| 字段 | 含义 |
|---|---|
| `source` | `live` = 实时抓取成功；其他值 → 前端显示"非实时"横幅 |
| `data_date` | 数据所属日期（北京时间 `YYYY-MM-DD`） |
| `server_day` | **服务端留痕**：抓取时页面顶部的「第N周 星期X」原文（如 `2026-2027 秋 第3周 星期三`）。拿它与 `data_date` 对照，事后可直接判断是否串天，不必重新登录 |
| `buildings` | 目标楼栋清单：第一公共教学楼、第二公共教学楼 + 北区两栋（教学B / 教学C）；覆盖范围已定稿，不再新增 |
| `classrooms[].b` | 楼栋名（教务系统返回的原名，精确匹配） |
| `classrooms[].g` | **界面分组**：北区四栋统一为 `北区`，其余楼栋的 `g` 等于自身楼栋名。前端据此做两级导航 |
| `classrooms[].room` / `.cap` | 房号 / 座位数 |
| `classrooms[].occ` | **占用位掩码**：1 / 2 / 4 / 8 / 16 = 五大节 |

小节 → 大节映射（`crawler/rooms_parser.py`）：

```
(1,2) → 第1大节   (3,4) → 第2大节   (5,6) → 第3大节   (7,8) → 第4大节   (9,10) → 第5大节
```

### 5.0 为什么必须在抓取前校验服务端日期

抓取在北京 04:00 跑，而 `data_date` 用的是**本地**日期。若教务系统的"今天"翻篇晚于 04:00，
抓到的会是昨天的课表，却被标成今天的日期 —— 页面显示 `source=live`、日期是今天，**没有任何报错**。
这类"静默给出错误数据"正是本项目最忌讳的事故类型（见 `docs/代码审查报告.md`），因此加了这道闸。

服务端翻篇的准确时刻**尚未实测**（只能靠跨零点采样确定）。已掌握的下界：
历史抓取在北京 07:42 拿到的数据已是当天的新数据 → **07:42 之前一定已翻篇**；
04:00 是否也已翻篇，**未验证**，所以不能只靠时间假设，必须有上面这道校验兜底。

### 5.1 已知边界（诚实记录）

- 小节 → 大节是"任一子小节有课即整节占用"（保守判定）
- 若某小节在响应中缺席，该大节按**未知**处理（不计为占用）。
  首选 JSON 接口会返回全部小节，正常不会出现；HTML 版解析器（`rooms_parser.py`）作为兜底保留，
  在响应不完整时可能把"未知"呈现为"空闲" —— 这是**已知的宽松行为**，不是数据伪造，但值得留意
- 教室类型字段 `t` **全空**，不可用于筛选或展示（数据缺失，非本项目可解）
